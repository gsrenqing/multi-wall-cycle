# 杀毒软件报毒说明（请先读这个）

## 一、结论：这是误报，不是病毒

`MultiWallCycle.exe` 是一个用 .NET Framework 的 csc 直接编译的单文件小程序，源码就在同一交付包的 `源码\` 目录里（13 个 `.cs` + 1 个 `.manifest`，全部可读），编译命令写在 `build.bat` 里。你随时可以自己重新编译、核对二进制。

它做四件事：读你的壁纸文件夹、调 Windows 自带的 `IDesktopWallpaper` COM 接口换壁纸、下载必应官方接口给的图片、在注册表 `Run` 键里写一条开机自启。除此之外不联网、不上传、不驻留服务、不弹广告。

## 二、为什么会被报（几类常见触发点）

| 行为 | 为什么像病毒 | 实际用途 |
| --- | --- | --- |
| 未签名的自编译 exe | 没有数字证书、不是大厂出品，启发式引擎默认降权 | 个人开源小工具，没有买证书 |
| 写 `HKCU\...\CurrentVersion\Run` | 恶意软件经典的自启手法 | 「开机自动启动」勾选项 |
| 删除时把自己移进回收站 | 少见行为，像"删痕迹" | 「卸载」要把 exe 本体也清掉 |
| 下载 `cn.bing.com` 的图片 | 有网络行为 | 「必应每日壁纸」来源 |
| 运行时反复写 `config.json` | 频繁磁盘写入 | 保存换图进度，防止重启回到第 1 张 |
| 截图/图标相关 API 调用 | 屏幕类 API 敏感 | 只是用 `System.Drawing` 画托盘图标与壁纸文字 |

**v2.3 新增的触发点**：程序改名后，企业/云端信誉库（如 360、火绒、Defender 的云查杀）里没有这个新文件名与新哈希的记录，"第一次见到的陌生程序"会被先拦后放——这是改名类更新最常见的误报原因。

## 三、已经做的减误报处理

- 不打包、不压缩、不加壳、不混淆——单 exe，字符串可读。
- 正式版**不写日志文件**，不在磁盘留长期痕迹。
- 只在需要时联网（勾了必应才会访问必应接口），不常驻后台监听。
- 卸载时**不删你的图片**，只清自己生成的文件。
- 提供完整源码与编译脚本，二进制可复现。

## 四、在本机怎么解决（三选一，按推荐顺序）

### 方案 1：加入信任区（最快，一分钟）

- **火绒**：主界面 → 防护中心 → 信任区 → 添加文件 → 选中 `MultiWallCycle.exe`。
- **Windows Defender**：设置 → 隐私和安全性 → Windows 安全中心 → 病毒和威胁防护 → 管理设置 → 排除项 → 添加排除项 → 文件。
- **360**：木马查杀 → 右下"信任区" → 添加文件。

加完再运行，后续更新版本时如果又报，把新 exe 重新加一次（哈希变了）。

### 方案 2：用测试版排查、正式版常驻

测试版（`_test\MultiWallCycle_Test.exe`）会写 `log.txt`。如果正式版出现异常行为，先用测试版复现并在配置目录看日志，正式版平时只作常驻使用。

### 方案 3：提交误报申诉（一劳永逸）

各家都有"误报反馈"入口，提交时附上：

1. 文件哈希（见 `sha256.txt`）；
2. 说明这是 .NET 自编译的壁纸轮换工具、源码随包提供；
3. 打包上传源码目录。

一般 1–3 个工作日会修正云端判定。

## 五、最彻底的办法：自己编译

1. 打开 `build.bat`，确认里面只有 `csc.exe` 一条编译命令（14 个源文件 + manifest + `app.ico` 图标资源）；
2. 双击运行，产物是 `成品\MultiWallCycle.exe`；
3. 想加日志排查就用 `build-test.bat`，产物是 `_test\MultiWallCycle_Test.exe`。

自己编出来的二进制，你清楚它每一行干什么。

## 六、文件完整性核对

| 文件 | 大小 | SHA256 |
| --- | --- | --- |
| `成品\MultiWallCycle.exe` | 330,240 字节 | `C04B7081D1ED699261245E3F000CEEF9711CD09C3DE8ECBBF8E2602E1D9F6CED` |
| `_test\MultiWallCycle_Test.exe` | 342,016 字节 | `858F9C0F1D81706BBA8983326ED6DE3165664B10031D650F3502F2D94B897E05` |

> 体积比 v2.3（321,024 字节）只多了 9,216 字节（新增 JPEG 元数据读写模块），图标部分与 v2.3 完全相同。体积比 v1.1.3（108,032 字节）大，是因为程序图标以两种形态编进了 exe：Win32 图标资源（约 105 KB，给资源管理器/任务栏）与托管资源（约 105 KB，给运行期托盘/窗口用）。**这不是"注入了什么东西"**，两层都是同 7 帧的 `app.ico`，可用 `ExtractAssociatedIcon` 取回验证。

核对方法（PowerShell 或命令提示符）：

```
certutil -hashfile MultiWallCycle.exe SHA256
```

哈希一致说明文件没被第三方改动过；若不一致，别运行，重新从原始包取。

## 七、如果杀软报的是具体威胁名

| 报法 | 含义 | 处理 |
| --- | --- | --- |
| `Trojan:Win32/Wacatac` / `Wacapew` | Defender 对"未知自编译程序"的通用启发式标签，几乎什么都会套 | 加排除项；或提交误报 |
| `HackTool` / `RiskWare` | 认为具备"修改系统"能力 | 同上，属于行为判定而非特征匹配 |
| `Win32:Malware-gen`（Avast/AVG） | 通用基因名 | 同上 |
| 具体到 `Backdoor` / `Ransom` 等 | 极少见，通常是被别的文件感染或下载器夹带 | 先用 `sha256` 核对，不一致就不要运行 |

## 八、为什么我不建议"为了不报毒而阉割功能"

去掉自启写入、去掉卸载自删、去掉联网取图，报毒可能少一点，但这三件事正是这个程序的用途本身。合理做法是：**源码公开 + 哈希公布 + 用户自选信任**，而不是为了通过启发式引擎把功能砍掉。
